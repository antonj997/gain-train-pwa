# Gain Train
<!-- impeccable:product-schema 1 -->

## Platform
web — phone-first React PWA, also usable on desktop.

## Users and purpose
A lifter logging sets between exercises, often one-handed. Start, resume, record actual performance, finish, and review comparable history with minimal administration.

## Operating context
Local IndexedDB saves precede cloud synchronization. The app remains usable without an account and caches production files for offline use. Routines and prior results speed repeated sessions. Numeric keyboard hints, clear save status and readable completed values are core affordances.

Settings Profile saves bodyweight in kg to an account-scoped local cache first. Decimal points and commas are accepted; blank clears the value, and a saved value must be greater than zero and at most 1000 kg. Signed-in changes queue for Supabase Auth metadata synchronization under gain_train_profile. A connection captures its account and access token, stops after account changes, and leaves failed or in-flight later edits queued. Profile metadata is editable data, never authorization. No database migration is required.

Uncompleted BW sets show registered bodyweight when available. Completing a BW set captures an optional bodyWeightKg snapshot; completed values do not follow later profile edits. New and repeated sets clear old snapshots. Existing completed sets without a snapshot remain valid and display BW.

One “Edit sets” toggle in each exercise’s … menu exposes compact numeric/type/completion/removal rows and the shared ordering control used by routine planning. The menu stays open while the switch is used, with a visible track and On/Off state. Closing Options, opening another exercise’s menu, moving focus outside the exercise or clicking outside it disables editing. Escape closes Options and returns focus to its trigger; Escape during set reordering first cancels that move. Outside pointer dismissal waits for click activation so controls do not move before the tap finishes. Set values use single-line text inputs with decimal or numeric keyboard hints and select on focus and repeated click. Custom pointer selection prevents native selection-drag auto-scroll; normal scrolling outside the input and handle-only reordering remain available. Copy, select-all and browser find modifier shortcuts remain available. Automated controller/component tests cover this behavior; native gestures have not been verified. Set types are ordered Warm-up, Working set, Cool-down. Pointer or keyboard reordering commits once at drop; cancel leaves order unchanged. Historical sessions retain Save/Discard.

Checked set values remain read-only in logging, compact and historical editors until explicitly unchecked. An input attempt shows the short red instruction “Uncheck this set to edit its values.” and highlights the matching completion button, which remains reachable in compact mode. Group load/measure/Extra weight changes leave checked rows unchanged; mixed rows retain individual load and reps/seconds captions. Blank unfinished rows suppress “Enter reps to complete this set.” and “Enter kg, or choose Bodyweight above.” Actual invalid-value feedback remains visible.

Incomplete strings such as “1e” belong to the local editor's optional inputText recovery field, carried by changeSetNumber/getSetInputText and accepted by recoverySet for workout and routine drafts. They survive remount/recovery without becoming numeric values or disappearing as blank fields. validSet rejects pending raw text and validate blocks saving it. Correcting the entry clears that field; saved records retain the existing numeric weight/reps schema.

Bodyweight exercises and routine plans offer an Extra weight switch for unfinished sets. The optional extraWeight flag keeps load:"bodyweight"; the normal weight field holds added kg only, with a valid completed value greater than zero and at most 10000 kg. A blank added-load field can remain unfinished. “BW + kg” and BW + added kg labels distinguish this mode from profile bodyweight. The independent bodyWeightKg snapshot retains profile kg at completion. New/repeated sets preserve added-load mode and kilograms while clearing completion/snapshots. Routines, backup validation, suggestions and previous-result matching preserve the mode; matching and analytics distinguish plain BW, added BW, assisted and weighted results, as well as reps and seconds. Added BW results compare reps/seconds at the same added kg and do not introduce a bodyweight estimated 1RM. The server load enum is unchanged and no database migration is required.

History opens on the current month and contains one calendar/date controller followed by the workout list. Two icon-only toggle buttons on one line change Month/Date range and Detailed/Simple; the date-filter icon offers connected From/To endpoints or a return-to-month calendar, while the view icon reflects the active display. Accessible labels, pressed states and titles explain them. Detailed retains the Monday-first grid; Simple uses 12px squares and compact 32px day controls, increased to 36px for coarse pointers, with full accessible date/workout counts. Selected ranges form a continuous band across adjacent dates with caps at visible row/month boundaries. Month mode filters by whole month or selected day. Date range uses compact From/To buttons and that same calendar for inclusive bounds across months. Browsing preserves chosen bounds; future dates are unavailable. One “Show current month” reset appears only away from the unfiltered current month. History has no general stats, “More periods” or second date picker.

Progress retains exercise progress and receives the original three general metrics and explanation: Workouts / active week, Avg duration · min and Exercises improving. Its clearly labelled Last 30 days summary shows the current and preceding 30-day dates and is independent of History's calendar selection.

## Constraints
Preserve existing records and sync compatibility. No destructive migration or real-account testing. Keep top mobile-wide toasts and directly reachable abandon-before-finish. The user explicitly requires immediate set deletion; confirm exercise deletion only when its sets contain values or completed data. No set/exercise Undo feature.

Allow one running workout: a nondeleted draft with a non-null startedAt. Blank starts, routine starts from Home or Routines, and History Repeat share the same confirmation when another workout is running. “Keep current workout” cancels without changing it; “Abandon and start” replaces and creates atomically, checking localVersion and revision so newly changed work requires confirmation again. Historical draft entries with startedAt:null remain allowed alongside a running workout.

Saving cannot resurrect a removed workout. Existing whole-workout Undo uses guarded restoreWorkout and cannot create a second running draft. Backup restore rejects the whole transaction if it would introduce two running drafts. These local storage guards require no record migration.
