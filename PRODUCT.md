# Gain Train

<!-- impeccable:product-schema 1 -->

## Platform

web — phone-first React PWA, also usable on desktop.

## Users and purpose

A lifter logging sets between exercises, often one-handed. Start, resume, record actual performance, finish, and review comparable history with minimal administration.

## Operating context

Local IndexedDB saves precede cloud synchronization. The app remains usable without an account and caches production files for offline use. Routines and prior results speed repeated sessions. Numeric keyboard hints, clear save status and readable completed values are core affordances.

Settings Profile saves bodyweight in kg to an account-scoped local cache first. Decimal points and commas are accepted; blank clears the value, and a saved value must be greater than zero and at most 1000 kg. Signed-in changes queue for Supabase Auth metadata synchronization under gain_train_profile. A connection captures its account and access token, stops after account changes, and leaves failed or in-flight later edits queued. Profile metadata is editable data, never authorization. No database migration is required.

Uncompleted BW sets show registered bodyweight when available. Completing a BW set captures an optional bodyWeightKg snapshot; completed values do not follow later profile edits. New and repeated sets clear old snapshots. Existing completed sets without a snapshot remain valid and display BW.

The workout screen is a sticky top bar over exercise cards. The top bar holds back, the workout name (tap it for the Workout details sheet: name, date, duration), one status line (elapsed time, “N of M sets” and save status; a past workout shows its date as a tappable chip in place of the timer) and Finish. Finish is an outline while any set is unchecked and fills with a slow accent gradient once every set is checked (static under reduced motion). Finish becomes Save when editing a completed workout, enabled only when something changed. A workout nobody named (still “Workout”) is named on Finish, and titled live in the top bar, after the routine it came from, else the plan's day type or group, else the main categories its exercises train, most common first and at most three (“Back & Arms”, “Chest, Shoulders & Arms”; each exercise counts once for its main category only, so a back day's rows never make it an arms day; ties go to more sets, then to the first), else its first exercises when none has a known category (“Bench Press, Pull Up”); typed names and stored history are never renamed. Every duration uses one format: “<1 min”, “45 min”, “1 h 53 min”. Each card has the exercise name, a muted “Last: 19 Oct” and a ⋯ button (and, when the working sets, not counting warm-ups, cool-downs or drops, differ from the last session the Previous column reads, a muted “3 working sets · last time 4”; nothing when they match or there is no last session), then column headings Set · Previous · load · count · Done and one 44px line per set: badge, previous result, load, count, ✓. Only the two values and ✓ are edited in the row; everything else opens a sheet:

- **Set sheet** (tap the badge): Warm-up / Working / Cool-down, the load for this set, Add drop and Delete set. Deleting is immediate. The edited row stays visible above the sheet.
- **Column headings:** the load heading (kg, BW, +kg, Assist) opens a short menu, Kilograms (kg) / Pounds (lb), that sets the weight unit for the whole app; the count heading opens Reps / Reps + hold / Hold (seconds), which switches the exercise's unchecked sets (Hold makes them bodyweight).
- **Reps + hold** (optional, off by default): “Reps + hold” (“Reps + håll”) keeps the measure reps and puts a compact hold field (seconds per rep, whole seconds 0–600, “s” inside, number pad) next to reps; the heading reads “Reps · hold”. A new set copies the hold of the set above, a checked row reads “60 × 6 · 2 s” (“KV × 6 · 2 s” for bodyweight), and Previous, History and the exercise page show “60 kg × 6 · 2 s”. Records, best sets and estimated maxes ignore the hold and stay weight × reps. The choice is remembered per exercise in the synced `library` record (`repHold`, exercise ids) and used next time and in routines, whose planned sets carry the hold too. Plain Reps hides the field and keeps the values in unchecked sets (choosing Reps + hold again brings them back); a set checked while the field is hidden is logged without its hold. `holdSec` is an optional set field; no schema bump.
- **⋯ sheet:** Swap exercise first (accent, ArrowLeftRight; also in the routine editor), then Fields… for cardio, Reorder sets, Reorder exercises (“Ändra ordning på övningar”, when there are two or more) and Remove exercise (confirms only when the exercise has entered values or completed sets). Load and count is gone: the load changes per set in the Set sheet, the unit and the count in the column headings.
- **Reorder sets sheet:** drag handles or keyboard moves, committed once at drop, and a Done button. Cancel leaves the order unchanged, and Escape during a move cancels the move before it closes the sheet.
- **Reorder exercises sheet:** the workout's (or routine's) exercises with their set counts, each with the same drag handle as Reorder sets and ↑ / ↓ buttons; the exercise whose menu opened it is marked. Done (or closing the sheet) saves the new order once, with an “Exercises reordered” toast and Undo. It replaces Move up / Move down.
- **Finish sheet:** a summary of the sets that will be saved, “Save as a routine”, Save workout, Keep logging and Abandon workout.

A floating “Next set” chip appears only while the next unchecked set is off screen. A rest bar (time left, +30 s, Skip, then “Rest done”) floats at the bottom while resting and never appears when rest is off. Set values use single-line text inputs with decimal or numeric keyboard hints and select on focus and repeated click. Custom pointer selection prevents native selection-drag auto-scroll; normal scrolling outside the input remains available. Copy, select-all and browser find modifier shortcuts remain available. Automated controller/component tests cover this behavior; native gestures have not been verified. Historical sessions retain Save/Discard.

Each set keeps its own load, so one exercise can mix, for example, weighted sets with one bodyweight or assisted set. The exercise's most common load is its default and names the load heading (kg, BW, +kg, Assist); a set that differs carries a marker in its field: BW or 40 with a small kg. “+” (bodyweight plus weight) and “−” (assisted) always show, even when every set uses that load, since they change what the number means; an added set copies the set before it, marker included. A drop set continues the set above at a lower weight with no rest. It is added from the Set sheet (prefilled at 80% of the weight, rounded to 2.5 kg), follows only a working set or another drop, has no ✓ of its own and is checked, unchecked and saved with its set. Add set after a drop makes an ordinary working set. Sets and drops count as one set in “N of M sets”, drops are matched to the same drop of the previous result and never count as an exercise's best set, and History shows them as “↳ 80 kg × 4” under their set. `drop` is an optional set field; no schema bump. Records from an older app version with a misplaced drop are repaired by validation instead of rejected.

**Cardio exercises** (the catalogue's machines and any custom exercise in Cardio) log a time and the fields the exercise shows, with no reps or weight. Each exercise chooses its own fields with ⋯ → **Fields…** (“Fält…”), a sheet titled “Choose fields” (“Välj fält”) with a switch per field and a km / m / mi control under Distance: Time (always on, since a set needs a time to be checked), Distance, Pace (worked out from time and distance as min/km, or min/mi in miles; shown, never saved), Level, Incline %, Calories and Heart rate (average bpm). The defaults: Treadmill time, distance, incline; Exercise Bike and Cross Trainer time, distance, level; Rowing Machine and Ski Erg time and distance in metres; Stair Climber time, level, calories; any other time, distance, calories. The choice is saved for the exercise (built-in or custom) in the synced `library` record (`cardioFields`) and used next time, in routines too. Turning a field off only hides its column: values already typed stay in the set, and History, the exercise page and Progress list every value a set holds. Distance is always stored in metres and shown in the chosen unit. **Time is typed like a timer** (iOS Timer, Strong, Hevy) on the number pad: digits shift in from the right and the colons come by themselves, “4” is 0:04, “400” and “0400” are 4:00, “4500” is 45:00 and “13000” is 1:30:00; up to six digits mean h:mm:ss, Backspace takes the last digit off, and leaving the field rolls 60 seconds or minutes over (“90” shows 0:90 while typing and 1:30 after). Pasting “4:00” or “04:00” works. (Before, a bare number was minutes, so “0400” became 400 minutes, 6:40:00.) A hold's seconds stay a plain number of seconds. Up to four fields share one line (two lines of two under 380px) and more go in lines of three, so every value fits at 360px.

Checked set values remain read-only in a live workout until explicitly unchecked. Editing a completed workout (History → Edit workout) leaves checked values editable in place; every field error of a checked set shows under its row, and Save stays disabled with the status “Fix marked sets” until they are valid. In a live workout a tap on a checked value (lifted within 10 px and 500 ms, with no scroll; or keyboard focus) shows the short red instruction “Uncheck this set to edit its values.” and highlights the matching completion button; a drag that starts on a checked value scrolls the page instead. A checked row reads as plain text: no field outline, a muted “×” between load and reps (“s” after a hold's seconds; nothing for cardio). Load and count changes (the Set sheet and the column headings) leave checked rows unchanged. Blank unfinished rows suppress “Enter reps to complete this set.” and “Enter kg, or choose Bodyweight above.” Actual invalid-value feedback remains visible. A ✓ that can't be pressed yet stays tappable (aria-disabled): a tap shows one muted line under the row saying why, such as “Add reps to check this set.” or “Fill in or delete its drops to check this set.”, cleared by a tap or focus outside the row.

Incomplete strings such as “1e” belong to the local editor's optional inputText recovery field, carried by changeSetNumber/getSetInputText and accepted by recoverySet for workout and routine drafts. They survive remount/recovery without becoming numeric values or disappearing as blank fields. validSet rejects pending raw text and validate blocks saving it. Correcting the entry clears that field; saved records retain the existing numeric weight/reps schema.

Bodyweight exercises and routine plans offer an extra-weight load (“BW + kg” in the Set sheet) for unfinished sets. The optional extraWeight flag keeps load:"bodyweight"; the normal weight field holds added kg only, with a valid completed value greater than zero and at most 10000 kg. A blank added-load field can remain unfinished. “BW + kg” and the “+” marker distinguish this mode from profile bodyweight. The independent bodyWeightKg snapshot retains profile kg at completion. New/repeated sets preserve added-load mode and kilograms while clearing completion/snapshots. Routines, backup validation, suggestions and previous-result matching preserve the mode; matching and analytics distinguish plain BW, added BW, assisted and weighted results, as well as reps and seconds. Added BW results compare reps/seconds at the same added kg and do not introduce a bodyweight estimated 1RM. The server load enum is unchanged and no database migration is required.

The app has four bottom tabs: Train, History, Progress and Library. Each page has its own top bar (a muted line over a 28px title) and shows the sync, sign-in and conflict notices as banners beneath it; there is no global header. Signed out, Train's “Saved on this phone. Sign in to sync” banner has a close button; closing it is remembered on that device (local storage), and Settings' account row stays the way to sign in. Settings opens from the gear on Train and has a back button. The workout screen hides the tabs.

Train (`/`) is the start screen. Its title is today's date in the chosen language (“Wednesday 4 November”, “Onsdag 4 november”), with the settings gear level with its first line. It shows a resume card for each running workout, Start workout (secondary “Start a new workout” while one is running) and “Log a past workout”, which opens the new workout on its Workout details sheet so the date is picked first. The This week card has Monday-to-Sunday dots, “N of G workouts” (or “N workouts” without a goal) and a line with sets, time trained and, from two weeks, “W weeks in a row on goal”. Start a routine lists the three most recently used routines; the last workout has a Repeat button.

The weekly goal is 1–14 workouts a week, off by default, set in Settings → Training and stored with the other training preferences on the device. The streak counts consecutive finished Monday-to-Sunday weeks that met it; the current week joins once it does.

History opens on the current month with the simple calendar. Workouts are grouped by week (“This week”, “D–D Mon”, with workout and set totals) in rows that open the details sheet; a warm “New best” badge marks a workout that set a PR. The calendar controls are described in DESIGN.md. The details sheet (`/history?workout=<id>`, with `&set=<id>` to highlight one set) shows the name, date, duration and sets, four tiles (Sets, Volume, Time, Records), a read-only card per exercise with its checked rows (badges for warm-up, cool-down and drop, values with a muted ×); an exercise's name opens its exercise page. Repeat, Edit and Delete sit in a sticky footer, and Close (×) in the header; the sheet opens with focus on itself, not on Close, and Close's keyboard ring is drawn inside the button.

**A PR** is one of two records per exercise, against every earlier finished workout: the **heaviest weight** (the heaviest-lift rule: warm-ups never count, drops do, a tie on weight is no PR) or the **best set volume** (weight × reps of one weighted working set, no drops). An exercise's first session is never a PR, and neither is a lift with nothing of its kind earlier to beat. An exercise gets at most one “PR” chip per workout, on the record set; when the two records fall on different sets the chip goes on the heaviest set. A line under the exercise's name names the records: “Record: Heaviest weight · Best set volume” (“Rekord: Tyngsta vikt · Bästa setvolym”). The Records tile counts the exercises with a PR, History's “New best” badge and Progress's Recent bests follow the same rule (`prEvents` in `src/data/exercise-records.ts`). Best est. 1RM, most reps and best session volume are records on the exercise page, not PRs.

**Better than last time.** A checked working set (not a warm-up, cool-down or drop) that beat the set in the same position last time, as the Previous column matches it, has a small muted-green up arrow (“Better than last time”, “Bättre än förra gången” for screen readers): more load at the same reps or more, the same load with more reps (a timed hold: more seconds), or for weighted and added-weight reps sets a higher weight × reps with the load not lower. Assisted sets count less assistance as more load; with reps + hold the hold must not be shorter, and the same load and reps with a longer hold counts too. Cardio has no arrow. It shows in History details, the exercise page's History and, after Previous, on the workout screen's checked rows (`improvedSince` in `src/data/set-improvement.ts`).

Progress is statistics and goals. Stats has a 4 weeks / 3 months / Year control driving four tiles (workouts per week over finished weeks only, working sets, volume, time trained, each against the previous period), up to four Recent bests (the latest PR of each exercise in the period, with the records it set) and the exercise list with sparklines, most sessions first. A Recent best opens the workout it was set in with that set highlighted; its exercise name opens the exercise page, as does each exercise row.

**The exercise page** (`/exercise/<id>`, a sub-page that pushes in like Settings; Back returns where it was opened) is the one place for an exercise, opened from Library → Exercises (built-in and custom), Progress, Recent bests, History details and lift goal cards. Its header has the name, the main category with the others muted, the equipment, a star and the Library ⋯ menu (Favourite, Edit and Share for custom exercises, Hide). Overview | History | Records (`?tab=`): Overview is the former Progress detail (latest working set, best e1RM, latest change, sessions, Heaviest lift, chart) or, for cardio, the latest session and time, distance, pace, calories and average heart rate over 30 days where they were logged; History lists every finished workout with the exercise, newest first, with its checked sets, each opening that workout; Records lists the best estimated 1RM, heaviest weight, most reps, best set volume and best session volume, and the most reps at each weight, each opening the workout with the set highlighted. Warm-ups never count; drops count only towards the heaviest weight and session volume (rules in `src/data/exercise-records.ts` and the [rework design](docs/superpowers/specs/2026-11-04-progress-library-rework.md)). “Start workout with this exercise” starts a blank workout with it, prefilled from last time. Edit opens the Library editor (`/library?tab=exercises&edit=<id>`).

Library (`/library`) is the training setup: Routines (the workouts you repeat), Exercises (the catalogue plus your own) and Plan (phases), chosen with the Segmented control and kept in `?tab=`, with one helper line under it for the chosen section; `/routines` and `/my-exercises` redirect to the matching tab. Routine cards show exercises, sets and when it was last done, with Start, Edit and a ⋯ sheet for Delete (with undo); “New routine” opens the editor sheet. Exercises has search, the chips All / Mine / Shared / Recently used / Hidden in one sideways-scrolling row, the groups Favourites, Recently used (up to five others) and A–Z, and “New exercise”. With a category chosen the list has three parts: favourites whose main category it is, then the category's other exercises under its name (“Ben”), then “Also trains Legs” (“Tränar även Ben”) for those where it is only a secondary category, each A–Z; while searching, favourites come first among equally good matches. The exercise picker groups the same way (All and Suggested: Favourites, Recently used, A–Z). A favourite shows a small filled warm star after its name, a mark rather than a button (read as “Favourite”); Favourite / Unfavourite is in the row's ⋯ menu and on the exercise page's header. Focusing the search, or typing, folds the chip rows away so the results get the room; a “Filter” chip with a count of active filters brings them back, and the filters keep applying. Every row opens the exercise page; a custom exercise's editor (which also deletes it) opens from its ⋯ menu or the exercise page; built-in exercises are not editable. Exercises can train several categories: catalogue compound lifts list others besides their main one (Deadlift is Back, also Legs and Glutes; Bench Press is Chest, also Arms and Shoulders; squats and lunges add Glutes; rows and pull-ups add Arms), and a custom exercise picks them as “Also trains” chips (`categories`, optional, not shared: `shared_exercises` keeps the main category). Category filters in Library and the picker, search and plan suggestions match any of them; the muted line reads “Back · Legs, Glutes”. Ids and the stored main category never change. Names may repeat, so custom exercises carry a “Mine” chip in Library and in the exercise picker, and the editor and the picker's create form warn (without blocking) when the name matches another exercise ignoring case and accents: “You already have an exercise called X.”

Settings groups the account row, Training (bodyweight, weekly goal, rest timer, theme), Your data (backup, restore, storage) and Account (sign out, delete; signed out with the phone's own log, just a note, since the account row is the one sign-in entry). Conflict and quarantine notices stay as cards above the groups.

Planning and goals are optional and nothing requires them. **Plans** (Library → Plan, `?tab=plan`; `/library/plan` redirects) are synced `plan` records: a name, an exact period (two date fields), a cycle of 1–6 weeks, a template grid of weeks × Monday–Sunday and dated overrides set from an Upcoming month view. A cell is a routine, a group, a day type, Rest or empty. The template loops from the first week of the period (weeks run Monday–Sunday) and overrides win; nothing is planned outside the period. Two plans cannot overlap; saving one that does is refused with the name and dates of the other. A plan can be **paused** instead of deleted (the pause/play button on its row, or Pause plan / Resume plan in its editor; both save at once): a paused plan (`paused: true`, an optional field, no schema bump) shows as Paused in muted text, plans nothing on Train and blocks no other plan's dates, and resuming it into another plan's period is refused with the same overlap message. Delete stays, behind its confirmation. A plan is a **training phase** (the editor's subtitle reads “Phase · 12 weeks · 4 Nov – 24 Jan”): the period can be set as a length of 4–26 weeks (ending on the Sunday of the last week) or any end date, and a new or re-dated phase is at most 26 weeks. Each cycle week is Normal or **Deload**; presets set “3 + 1 deload”, “5 + 1 deload” or “No deload” and copy week 1 into new weeks (“Copy week 1 to the other weeks” does it later). A deload week trains the same routines, prefilled lighter: by default 10 % lighter and half the working sets, both adjustable per plan. An optional **Progression** (“Increase lifts over the phase”) holds lifts added one by one or as all of a routine's weighted exercises; each has reps, a start weight from recent history (or the routine, or typed), a target as a % or kg, a level (Beginner / Intermediate / Experienced, detected from the log and changeable), a suggested weekly step and timeline with its reasons, a warning with “Use suggested timeline” when the target is faster than usual, a week-by-week table whose weeks can be typed over, and “Also add as a goal” (a lift goal due when the phase ends). Starting a routine inside an active phase prefills progressed lifts with that week's planned weight and reps and, in a deload week, cuts the working sets and loads; the cards show a muted “Plan week 3: 85 kg” or “Deload week”, and Train's plan row reads “Week 3 of 12 · Deload”. Plan rows show the dates, the week of the phase, the cycle (“3 + 1 deload”) and the number of progressions. The rates, sources and data are in the [phase planning design](docs/superpowers/specs/2026-11-04-phase-planning-design.md). **Day types** (Legs, Push, Pull, Upper, Lower, Full body, Cardio) map to catalogue categories, matched against an exercise's main or other categories. **Groups** (e.g. “Legday”) hold chosen routines and optional categories and live in the synced `library` record next to the hidden exercises; they are for one plan day offering a choice of routines, so Library → Plan folds them under Advanced, and the day picker lists Routines, then Day types, then Groups. On Train a plan entry for today shows “Today: <name>” at the top of Start a routine: Start for a routine, each routine of a group, “Start with suggestions” for a day type or a group with categories (an empty workout that opens the picker on a Suggested filter of those categories), or “Rest day”; planned days are outlined in the week strip, and This week has a small Plan link. A deleted routine or group is ignored. The earlier device-only plan is imported once into a plan record (today to three months ahead, one-week cycle) and its local copy is removed. **Goals** are synced `goal` records, independent of plans (a plan may link to them): a bodyweight goal (target and the weight at the start, compared with the profile bodyweight) or a lift goal (exercise, weight × reps up to 10, compared with the heaviest checked set for one rep or the estimated one-rep max otherwise), each by a date. Progress has a Stats | Goals switch (Statistik | Mål), kept in the URL as `/progress?tab=goals`. Stats is the period view; when there are goals or a weekly goal it starts with a one-line link, “Goals: 2 active · this week 2/3”, that opens Goals. The Goals tab (“+ Add goal” top right) shows, in order: the **weekly goal** card (this week “2 of 3 workouts” with a bar and the days left in the week; “Met 3 of the last 4 weeks · 9 of 12”, counting only finished weeks from the week of the first workout; the current and best streak; a 12-week strip of bars against a dashed goal line, met weeks in the done colour; Edit opens the same sheet as Settings, and without a goal a “Set a weekly goal” card opens it); **Active goals**, nearest date first, each with a bar from the start to the target, Start → Now → Target, “N days left · by <date>”, “Due today” or “Overdue by N days”, the pace (On track, Ahead, Behind with the kg/week needed against the trend, or “Not enough data yet”), “At this pace you get there around <date>” and a sparkline since the goal started; and **Reached (N)**, folded, with “Reached on <date>”. With no goals there is an empty card with Add goal. A lift goal starts from its best before the goal was made or, with none, from the first session after it. The trend is a least-squares line through the last six weeks of readings (at least three over two weeks): a lift reads each session's best set in the goal's measure, a bodyweight goal reads its starting weight, the bodyweight saved with checked bodyweight sets and the profile weight today (there is no separate weigh-in log). Ahead is 20% faster than needed, On track at least 90% of it; projections beyond two years are not shown.

**Sharing custom exercises** is optional and needs an account. From a custom exercise's ⋯ sheet, “Share to library” publishes its name, category, and any equipment, aliases, load and measure to the `shared_exercises` table; the returned id is saved on the exercise as `sharedId` and “Stop sharing” deletes the row and clears it. Signed-out users see “Sign in to share”; a network error shows a toast and leaves everything as it was. Library → Exercises → Shared lists other people's shared exercises (fetched when the chip is chosen, cached in memory for a minute, no realtime; your own and ones you already added are left out) with the same search and filters and an Add button. Add copies the row into your custom exercises with `sharedFrom` set, so the copy keeps working if the original is unshared, and it can be hidden like any exercise. Signed out or offline the chip shows a short note. `sharedId`, `sharedFrom`, `equipment`, `aliases`, `load` and `measure` are optional fields on a custom exercise; no schema bump.

**Sharing routines** works the same way. A routine's ⋯ sheet (Library → Routines) has “Share to library”, “Stop sharing” or, signed out, “Sign in to share”. Publishing writes a row to `shared_routines` with the routine's name and a payload of its exercises and the structure of their planned sets: each set's section (warm-up, working, cool-down), drop, load (weight, bodyweight with or without extra weight, assisted) and measure (reps, seconds, cardio), with `holdSec: null` marking reps + hold. No values travel: reps and weight are null, and the hold, cardio fields, done state, bodyweight, typed text and ids are null or left out (`toSharedSet` / `stripSharedRoutine` in `src/lib/shared-routines.ts`). Updating the shared copy sends the same, so changing only weights or reps no longer updates it. The payload holds built-in exercises by their stable `builtin:` id, the user's own exercises with their definition (name, category, equipment, aliases, load, measure, note, and the shared exercise they are or came from). At most 40 exercises and about 60 KB; the server also limits each person to 20 shared routines a day and 100 in all. The row's id is saved on the routine as `sharedId`; saving the routine updates the shared copy, and deleting it removes the row first (Undo brings it back unshared). Library → Routines has Mine/Shared chips; Shared lists every shared routine with “by <name>” (or “by someone”), the exercise count and first names, and Add. Your own show “Mine” and ones you added show “Added”. Tapping a row opens a full preview sheet: name, “by <name>” (or “Shared by you”), note, the main categories (picked as an unnamed workout's name picks them), exercise and set counts (and, for your own, the average length from your history), then each exercise in order with a structural summary (“3 sets · 1 warm-up · 1 drop”) and a line per set type (“Warm-up · 1 × Weight · reps”, “2 × Weight · reps · 1 drop”); the sharer's exercises you don't have yet are marked “New exercise” (“Ny övning”). Its sticky footer has “Add to my routines” (“Lägg till i mina rutiner”) for someone else's routine, disabled as “In your routines” once added, and for your own Edit, which opens your routine's editor, and Stop sharing, after a confirm. Add copies the routine with `sharedFrom` set and creates the sharer's own exercises, reusing one of yours copied from the same shared exercise or with the same name and category. Every set is stripped again on add, so rows published before values were left out arrive empty too; the routine editor shows empty fields and starting a workout fills them from your own last results, as for a new routine. `sharedId` and `sharedFrom` are optional routine fields; no schema bump.

**Display name.** Signed in, Settings → Account has a Name row (1–40 characters, saved to the `profiles` table, removable). It is shown as “by <name>” on routines and exercises you share, and as the title of the account row. Names are not readable by others directly: only the shared feeds (`shared_routine_feed()`, `shared_exercise_feed()`) return the sharer's name, and neither returns who shared a row.

**Feedback and the admin inbox.** Settings → Help and feedback → Send feedback opens a full-size sheet: Bug or Feature idea, a title (required, at most 120 characters), a description (at most 5000), up to four images and an “Include technical details” switch (on for bugs, off for ideas until changed) that adds the build (commit and date), language, user agent, viewport, screen, whether it runs installed, and the last crash the error screen saw (`gt-last-error`). Images are redrawn on the phone as JPEG with a 1600 px long edge (quality 0.82); a file that will not open is left out with a message. Send uploads the images to the private `feedback` bucket at `<uid>/<report id>/<n>.jpg`, then inserts the `feedback_reports` row; if anything fails the uploads are removed and the error shown. Offline, Send says so and the draft stays (it is kept while Settings is open, not stored). Below the form, My reports lists the user's own reports with their status (Open, Planned, Done, Won't fix) and the admin's reply. Signed out, the row opens a short sheet with a sign-in link. At most 10 reports a day per person. Admins (the `app_admins` table, seeded with the owner's account; `is_admin()` is asked once a session) also see an Admin row with the open count, which opens `/settings/admin`: status chips (Open by default, Planned, Done, Won't fix, All, with counts), Bugs/Feature ideas chips, and rows with the reporter's display name or email, the age and the image count. A report opens in a full-size sheet with the description, images (hour-long signed URLs, tap for full size), collapsible technical details, a status picker, a note shown to the reporter, Save and Delete (removes the images too). Anyone else sees “Not available”. Reports outlive a deleted account (the reporter becomes null); the delete-account function removes that person's images first, because Supabase will not delete a user who owns storage objects.

**Language** is English or Swedish, chosen per device in Settings → Training → Language (`gt-language` in local storage; it does not sync). English is the default. A device that already holds a log (workouts, routines, exercises, plans, goals or a bodyweight) and has never chosen is asked once, “Choose your language · Välj språk”; closing that sheet keeps English. A new user is not asked: English is remembered silently. Everything on screen follows the choice, including dates, weekday letters (M T O T F L S in Swedish), and decimals (a comma in Swedish; set fields accept both). Stored data stays English: built-in exercise names, category, equipment and day-type values are translated only when shown, and search also matches the Swedish labels. Messages live in `src/i18n` (`en.ts` is the source of truth; `sv.ts` must have the same keys).

**Weight unit** is kg or lb, chosen per device from a load column heading or Settings → Training → Weight unit (`gt-weight-unit`; it does not sync). Weights are always stored in kg: pounds are shown to one decimal (trailing .0 dropped, 1 lb = 0.45359237 kg) and typed pounds are stored as kg to the gram, so they show the same pounds again; a field that is not edited keeps its exact kg. Set fields and markers, Previous, the bodyweight readout, History, routine previews, Progress (latest and best sets, estimated 1RM, its chart and baseline, volume as lb or “k lb”), goal titles, values and pace and the Settings bodyweight row follow the unit. Still in kg: the bodyweight and goal entry fields (labelled “(kg)”) and validation messages. Helpers: `src/lib/units.ts`, tested.

## Constraints

Preserve existing records and sync compatibility. No destructive migration or real-account testing. Keep top mobile-wide toasts; they start just below the page header or the workout's top bar (useToastClearance), and at most two show at once, the newest in front. Abandon lives in the Finish sheet; the owner approved moving it there from the top bar on 28 October 2026. It keeps the undo toast. The user explicitly requires immediate set deletion; confirm exercise deletion only when its sets contain values or completed data. No set/exercise Undo feature.

Allow one running workout: a nondeleted draft with a non-null startedAt. Blank starts, routine starts from Train or Library, and History Repeat share the same confirmation when another workout is running. “Keep current workout” cancels without changing it; “Abandon and start” replaces and creates atomically, checking localVersion and revision so newly changed work requires confirmation again. Historical draft entries with startedAt:null remain allowed alongside a running workout.

Saving cannot resurrect a removed workout. Existing whole-workout Undo uses guarded restoreWorkout and cannot create a second running draft. Backup restore rejects the whole transaction if it would introduce two running drafts. These local storage guards require no record migration.
