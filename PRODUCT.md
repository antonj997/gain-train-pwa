# Gain Train

<!-- impeccable:product-schema 1 -->

## Platform

web — phone-first React PWA, also usable on desktop.

## Users and purpose

A lifter logging sets between exercises, often one-handed. Start, resume, record actual performance, finish, and review comparable history with minimal administration.

## Operating context

Local IndexedDB saves precede cloud synchronization. The app remains usable without an account and caches production files for offline use. Routines and prior results speed repeated sessions. Numeric keyboard hints, clear save status and readable completed values are core affordances.

Settings Profile saves bodyweight in kg to an account-scoped local cache first. Decimal points and commas are accepted; blank clears the value, and a saved value must be greater than zero and at most 1000 kg. Signed-in changes queue for Supabase Auth metadata synchronization under gain_train_profile. A connection captures its account and access token, stops after account changes, and leaves failed or in-flight later edits queued. Profile metadata is editable data, never authorization. No database migration is required.

Uncompleted BW sets show registered bodyweight when available. Completing a BW set captures an optional bodyWeightKg snapshot; completed values do not follow later profile edits. New and repeated sets clear old snapshots. Existing completed sets without a snapshot remain valid and display BW.

The workout screen is a sticky top bar over exercise cards. The top bar holds back, the workout name (tap it for the Workout details sheet: name, date, duration), one status line (elapsed time, “N of M sets” and save status; a past workout shows its date as a tappable chip in place of the timer) and Finish. Finish becomes Save when editing a completed workout, enabled only when something changed. A workout nobody named (still “Workout”) is named on Finish, and titled live in the top bar, after the routine it came from, else the plan's day type or group, else its first exercises (“Bench Press, Pull Up”, “Bench Press + 2 more”); typed names and stored history are never renamed. Every duration uses one format: “<1 min”, “45 min”, “1 h 53 min”. Each card has the exercise name, a muted “Last: 19 Oct” and a ⋯ button, then column headings Set · Previous · load · count · Done and one 44px line per set: badge, previous result, load, count, ✓. Only the two values and ✓ are edited in the row; everything else opens a sheet:

- **Set sheet** (tap the badge): Warm-up / Working / Cool-down, the load for this set, Add drop and Delete set. Deleting is immediate. The edited row stays visible above the sheet.
- **Load and count sheet** (tap a column heading, or ⋯ → Load and count): Weight / Bodyweight / Assisted with an “Add extra weight” switch, and Reps / Seconds. It applies to unchecked sets only.
- **⋯ sheet:** Load and count, Reorder sets, Move up, Move down and Remove exercise (confirms only when the exercise has entered values or completed sets).
- **Reorder sets sheet:** drag handles or keyboard moves, committed once at drop. Cancel leaves the order unchanged, and Escape during a move cancels the move before it closes the sheet.
- **Finish sheet:** a summary of the sets that will be saved, “Save as a routine”, Save workout, Keep logging and Abandon workout.

A floating “Next set” chip appears only while the next unchecked set is off screen. A rest bar (time left, +30 s, Skip, then “Rest done”) floats at the bottom while resting and never appears when rest is off. Set values use single-line text inputs with decimal or numeric keyboard hints and select on focus and repeated click. Custom pointer selection prevents native selection-drag auto-scroll; normal scrolling outside the input remains available. Copy, select-all and browser find modifier shortcuts remain available. Automated controller/component tests cover this behavior; native gestures have not been verified. Historical sessions retain Save/Discard.

Each set keeps its own load, so one exercise can mix, for example, weighted sets with one bodyweight or assisted set. The exercise's most common load is its default and names the load heading (kg, BW, +kg, Assist); a set that differs carries a marker in its field: BW, +10, −25, or 40 with a small kg. No marker appears while all sets share a load. A drop set continues the set above at a lower weight with no rest. It is added from the Set sheet (prefilled at 80% of the weight, rounded to 2.5 kg), follows only a working set or another drop, has no ✓ of its own and is checked, unchecked and saved with its set. Add set after a drop makes an ordinary working set. Sets and drops count as one set in “N of M sets”, drops are matched to the same drop of the previous result and never count as an exercise's best set, and History shows them as “↳ 80 kg × 4” under their set. `drop` is an optional set field; no schema bump. Records from an older app version with a misplaced drop are repaired by validation instead of rejected.

Checked set values remain read-only in a live workout until explicitly unchecked. Editing a completed workout (History → Edit workout) leaves checked values editable in place; every field error of a checked set shows under its row, and Save stays disabled with the status “Fix marked sets” until they are valid. In a live workout an input attempt shows the short red instruction “Uncheck this set to edit its values.” and highlights the matching completion button. Load and count sheet changes leave checked rows unchanged. Blank unfinished rows suppress “Enter reps to complete this set.” and “Enter kg, or choose Bodyweight above.” Actual invalid-value feedback remains visible. A ✓ that can't be pressed yet stays tappable (aria-disabled): a tap shows one muted line under the row saying why, such as “Add reps to check this set.” or “Fill in or delete its drops to check this set.”, cleared by a tap or focus outside the row.

Incomplete strings such as “1e” belong to the local editor's optional inputText recovery field, carried by changeSetNumber/getSetInputText and accepted by recoverySet for workout and routine drafts. They survive remount/recovery without becoming numeric values or disappearing as blank fields. validSet rejects pending raw text and validate blocks saving it. Correcting the entry clears that field; saved records retain the existing numeric weight/reps schema.

Bodyweight exercises and routine plans offer an Extra weight switch (“Add extra weight” in the Load and count sheet) for unfinished sets. The optional extraWeight flag keeps load:"bodyweight"; the normal weight field holds added kg only, with a valid completed value greater than zero and at most 10000 kg. A blank added-load field can remain unfinished. “BW + kg” and the “+” marker distinguish this mode from profile bodyweight. The independent bodyWeightKg snapshot retains profile kg at completion. New/repeated sets preserve added-load mode and kilograms while clearing completion/snapshots. Routines, backup validation, suggestions and previous-result matching preserve the mode; matching and analytics distinguish plain BW, added BW, assisted and weighted results, as well as reps and seconds. Added BW results compare reps/seconds at the same added kg and do not introduce a bodyweight estimated 1RM. The server load enum is unchanged and no database migration is required.

The app has four bottom tabs: Train, History, Progress and Library. Each page has its own top bar (a muted line over a 28px title) and shows the sync, sign-in and conflict notices as banners beneath it; there is no global header. Signed out, Train's “Saved on this phone. Sign in to sync” banner has a close button; closing it is remembered on that device (local storage), and Settings' account row stays the way to sign in. Settings opens from the gear on Train and has a back button. The workout screen hides the tabs.

Train (`/`) is the start screen. Its title is one line picked at random from about 25 (plain, dry, encouraging, odd; under 40 characters, no emoji or exclamation marks, never the previous pick), with today's date above it. It shows a resume card for each running workout, Start workout (secondary “Start a new workout” while one is running) and “Log a past workout”, which opens the new workout on its Workout details sheet so the date is picked first. The This week card has Monday-to-Sunday dots, “N of G workouts” (or “N workouts” without a goal) and a line with sets, time trained and, from two weeks, “W weeks in a row on goal”. Start a routine lists the three most recently used routines; the last workout has a Repeat button.

The weekly goal is 1–14 workouts a week, off by default, set in Settings → Training and stored with the other training preferences on the device. The streak counts consecutive finished Monday-to-Sunday weeks that met it; the current week joins once it does.

History opens on the current month with the simple calendar. Workouts are grouped by week (“This week”, “D–D Mon”, with workout and set totals) in rows that open the details sheet; a warm “New best” badge marks a workout that set a best estimated 1RM against all earlier ones (drops never count). The calendar controls are described in DESIGN.md.

Progress has a 4 weeks / 3 months / Year control driving four tiles (workouts per week over finished weeks only, working sets, volume, time trained, each against the previous period), up to four Recent bests and the exercise list with sparklines; an exercise opens its detail and chart in a sheet.

Library (`/library`) has Routines and Exercises, chosen with the Segmented control and kept in `?tab=`; `/routines` and `/my-exercises` redirect to the matching tab. Routine cards show exercises, sets and when it was last done, with Start, Edit and a ⋯ sheet for Delete (with undo); “New routine” opens the editor sheet. Exercises has search, the chips All / Yours / Recently used, the groups Recently used (up to five) and A–Z, a favourite star and “New exercise”. A custom exercise opens its editor, which also deletes it; built-in rows are not editable. Names may repeat, so custom exercises carry a “Yours” chip in Library and in the exercise picker, and the editor and the picker's create form warn (without blocking) when the name matches another exercise ignoring case and accents: “You already have an exercise called X.”

Settings groups the account row, Training (bodyweight, weekly goal, rest timer, theme), Your data (backup, restore, storage) and Account (sign out, delete; signed out with the phone's own log, just a note, since the account row is the one sign-in entry). Conflict and quarantine notices stay as cards above the groups.

Planning and goals are optional and nothing requires them. **Plans** (Library → Plan, `?tab=plan`; `/library/plan` redirects) are synced `plan` records: a name, an exact period (two date fields), a cycle of 1–6 weeks, a template grid of weeks × Monday–Sunday and dated overrides set from an Upcoming month view. A cell is a routine, a group, a day type, Rest or empty. The template loops from the first week of the period (weeks run Monday–Sunday) and overrides win; nothing is planned outside the period. Two plans cannot overlap; saving one that does is refused with the name and dates of the other. **Day types** (Legs, Push, Pull, Upper, Lower, Full body, Cardio) map to catalogue categories. **Groups** (e.g. “Legday”) hold chosen routines and optional categories and live in the synced `library` record next to the hidden exercises. On Train a plan entry for today shows “Today: <name>” at the top of Start a routine: Start for a routine, each routine of a group, “Start with suggestions” for a day type or a group with categories (an empty workout that opens the picker on a Suggested filter of those categories), or “Rest day”; planned days are outlined in the week strip, and This week has a small Plan link. A deleted routine or group is ignored. The earlier device-only plan is imported once into a plan record (today to three months ahead, one-week cycle) and its local copy is removed. **Goals** are synced `goal` records, independent of plans (a plan may link to them): a bodyweight goal (target and the weight at the start, compared with the profile bodyweight) or a lift goal (exercise, weight × reps up to 10, compared with the heaviest checked set for one rep or the estimated one-rep max otherwise), each by a date. Progress → Goals shows a bar from the best before the goal was set to the target, now versus target, days left, and “Reached on <date>” once met.

**Sharing custom exercises** is optional and needs an account. From a custom exercise's ⋯ sheet, “Share to library” publishes its name, category, and any equipment, aliases, load and measure to the `shared_exercises` table; the returned id is saved on the exercise as `sharedId` and “Stop sharing” deletes the row and clears it. Signed-out users see “Sign in to share”; a network error shows a toast and leaves everything as it was. Library → Exercises → Shared lists other people's shared exercises (fetched when the chip is chosen, cached in memory for a minute, no realtime; your own and ones you already added are left out) with the same search and filters and an Add button. Add copies the row into your custom exercises with `sharedFrom` set, so the copy keeps working if the original is unshared, and it can be hidden like any exercise. Signed out or offline the chip shows a short note. `sharedId`, `sharedFrom`, `equipment`, `aliases`, `load` and `measure` are optional fields on a custom exercise; no schema bump.

## Constraints

Preserve existing records and sync compatibility. No destructive migration or real-account testing. Keep top mobile-wide toasts; they start just below the page header or the workout's top bar (useToastClearance), and at most two show at once, the newest in front. Abandon lives in the Finish sheet; the owner approved moving it there from the top bar on 28 October 2026. It keeps the undo toast. The user explicitly requires immediate set deletion; confirm exercise deletion only when its sets contain values or completed data. No set/exercise Undo feature.

Allow one running workout: a nondeleted draft with a non-null startedAt. Blank starts, routine starts from Train or Library, and History Repeat share the same confirmation when another workout is running. “Keep current workout” cancels without changing it; “Abandon and start” replaces and creates atomically, checking localVersion and revision so newly changed work requires confirmation again. Historical draft entries with startedAt:null remain allowed alongside a running workout.

Saving cannot resurrect a removed workout. Existing whole-workout Undo uses guarded restoreWorkout and cannot create a second running draft. Backup restore rejects the whole transaction if it would introduce two running drafts. These local storage guards require no record migration.
